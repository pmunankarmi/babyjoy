# BabyJoy WordPress

Conversion of BabyJoy9.57 into a WordPress theme and companion plugin.

## Local development

The Local app manages **BabyJoy** at `http://babyjoy.local`, with files under `/Users/puskar/Documents/Sites/babyjoy`. WordPress admin: `http://babyjoy.local/wp-admin/`. Use the WordPress credentials entered during Local creation.

The Local theme and BabyJoy Core are installed copies so admin updates cannot overwrite this source checkout. After source edits, run `python3 scripts/sync-local.py /Users/puskar/Documents/Sites/babyjoy/app/public`. Stop/start the site in Local. The temporary `.local/` SQLite installation is a verification sandbox, not the Local site.

## Required plugins

- WooCommerce: product catalogue, categories, attributes, variations, images and ordering.
- Advanced Custom Fields Pro: install your licensed copy; no license or premium plugin is included in this repository.
- Polylang: standard linked Arabic/English **page** translations.
- BabyJoy Core: install `build/babyjoy-core.zip` alongside the theme.

Do not install Polylang for WooCommerce. Products and variations deliberately have one record without a Polylang language assignment. Arabic titles, descriptions, benefits and attribute labels live in ACF on the same product. `/en/product/<slug>/` and `/ar/product/<slug>/` resolve that record. Product language links, canonicals and alternate links are generated by the theme.

The bundled `polylang-slug.php` is reused from the SAB project, originally Polylang Slug 0.2.3 by Ulrich Pogson. BabyJoy guards duplicate loading and excludes untranslated WooCommerce product lookups from its language SQL filter. Do not activate a second copy of Polylang Slug. If using Polylang Pro, its native shared-slug implementation takes precedence.

## Editing

Gutenberg and block widgets are disabled; use the classic editor and ACF fields.

- **Arabic from the English editor:** the theme’s Arabic translation panel resolves the linked record with `pll_get_post($english_id, 'ar')`. Its title, content and media load from and save directly to that Arabic page. Values are not duplicated on the English page. No additional plugin is needed.
- **Pages:** edit each linked translation using Polylang. ACF “Page content and media” exposes the imported text and media with descriptive headings; reference labels are hidden and only content is editable; layout stays in protected post metadata. Field order corresponds to the original layout: edit values without reordering or deleting imported rows. Add new layouts through theme development rather than changing row order.
- **Products:** edit native title, description, image, gallery, categories, attributes and ordering. ACF contains Arabic content, collection/type, benefits and regional retailer selection.
- **Products → Attributes:** the global Size attribute provides shared size terms. Variations select Size and their native image. Additional fields inside each variation hold minimum/maximum kg, pack counts and Arabic size label. Blank maximum means open-ended; blank minimum means unconfirmed and is excluded from weight recommendations.
- **BabyJoy Options:** site logo, contact email/phone/address, notification recipient, social links, per-site aggregators and translated interface/header/footer text. Logo uses the same attachment as Appearance → Customize → Site Identity.
- **Appearance → Menus:** separate native English and Arabic primary menus, selected by language. Shared slugs do not require duplicate templates.
- **Contact submissions:** private records visible to administrators, details view, and CSV export. Exports escape spreadsheet formula prefixes and include UTF-8 BOM for Arabic. Native WordPress privacy export/erasure includes these records.

The contact popup uses the original contact trigger and adds no promotional buttons. Submissions are stored even if notification delivery fails. Set a notification email and configure mail delivery on production; local notifications are disabled by default. CSV contains personal data and requires administrator access.

WooCommerce purchasing is disabled both in templates and server hooks, including Store API cart/checkout endpoints. Cart, checkout and account pages redirect home. Price and add-to-cart controls are omitted.

## Initial content import

`build/import-data.json` contains content extracted from the supplied source, not executable instructions. It contains public site content and source media references, no WordPress credentials.

On a **new site**, activate required plugins, BabyJoy Core and the BabyJoy theme, then run:

```sh
wp eval-file scripts/import-wordpress.php /absolute/path/to/build/import-data.json
```

The importer expects the repository layout with `wordpress-theme/babyjoy/assets` beside `build`. Run the importer again after language initialization to normalize shared slugs and native menu references. It reuses stored IDs but **overwrites imported page/product content and site settings**; do not run it on an edited production site. It never runs during theme activation or updates.

Original source is not required to install the packaged theme. To regenerate seed data, run `python3 scripts/prepare-source.py` after providing the source folder `BabyJoy9.57` or the original ZIP. This requires BeautifulSoup.

## Size guide

The browser receives published WooCommerce catalogue data generated server-side. It never maintains a separate hardcoded size table. Overlapping ranges prefer a size with 1.5 kg remaining before its upper boundary; otherwise the last matching size is chosen. Super Big Pants can be an alternative/fallback only when Pants is selected. Unknown ranges are available in manual-size mode but excluded from weight matching. The source’s Compressed Pants size 4 range remains unconfirmed; no weight range has been invented.

## GitHub releases and WordPress updates

Repository: https://github.com/pmunankarmi/babyjoy

1. Change theme version in `wordpress-theme/babyjoy/style.css` (and plugin version when relevant).
2. Commit changes and push a matching tag, for example `v1.0.1`.
3. GitHub Actions packages `babyjoy.zip` and `babyjoy-core.zip` as release assets.
4. WordPress discovers a higher theme version through its standard theme update checks. Use WordPress’s existing “Check again” control if needed; no custom update button is added. GitHub metadata is cached for one hour and transient failures for fifteen minutes.

A commit without a higher published release is not a theme update. The updater downloads only the named theme asset, not the entire repository archive. Database content, logo, settings and submissions are not replaced by theme updates. The companion plugin has its own installable ZIP; update it when a release changes plugin behavior.

## Validation and packaging

```sh
find wordpress-theme wordpress-plugin -name '*.php' -print0 | xargs -0 -n1 php -l
node --check wordpress-theme/babyjoy/assets/js/wordpress.js
wp eval-file scripts/verify-wordpress.php
python3 scripts/package.py
```

The integration check validates page translation links/shared slugs, single product records, catalogue restrictions, native Size attributes, aggregator options, logo synchronization, CSV escaping and a mocked higher GitHub release. The mock does not publish a release or install an update.
